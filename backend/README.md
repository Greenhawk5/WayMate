# WayMate — Cloudflare Workers Backend

میکروسرویس و زیرساخت سمت سرور برنامه تاکتیکی WayMate بر بستر Cloudflare Workers و پایگاه داده رابطه‌ای توزیع‌شده Cloudflare D1.

> [!NOTE]
> این مخزن صرفاً یک نمونه آموزشی و آزمایشی (Educational Prototype) است و فقط داده‌های ساختگی و شبیه‌سازی‌شده (Synthetic Data) را پردازش می‌کند. هیچ داده عملیاتی، پرسنلی یا موقعیت مکانی واقعی در آن پردازش یا ذخیره نمی‌شود. سرویس Cloudflare R2 طبق خط‌مشی پروژه به طور کامل از معماری کنار گذاشته شده است.

## ۲. متغیرهای محیطی و بایندینگ‌های Cloudflare (Bindings & Env)

تنظیمات در فایل `wrangler.jsonc` ثبت شده و از طریق `c.env` در دسترس است:

| نام بایندینگ / متغیر | نوع | توضیح |
| :--- | :--- | :--- |
| `DB` | `d1_database` | اتصال به دیتابیس D1 با نام `waymate-d1` |
| `ENVIRONMENT` | `string` | محیط اجرا (`development`، `staging`، `production`) |
| `API_VERSION` | `string` | نسخه رابط برنامه‌نویسی (`v1`) |
| `JWT_SECRET` | `secret` | کلید ۳۲ بایتی امضای HMAC-SHA256 (تنظیم در `.dev.vars` یا با `wrangler secret put`) |

### تنظیم متغیرهای محلی
برای اجرای محلی، یک فایل `.dev.vars` ایجاد کنید (این فایل در گیت نادیده گرفته می‌شود):
```bash
cp .dev.vars.example .dev.vars
```
محتوای `.dev.vars`:
```env
JWT_SECRET=super-secret-tactical-key-min-32-chars-for-dev!
ENVIRONMENT=development
```

## ۳. مایگریشن‌های پایگاه داده D1 (Database Migrations)

مایگریشن‌ها در مسیر `migrations/` با اسکریپت‌های SQL استاندارد و بدون تخریب داده‌های قبلی نگهداری می‌شوند:

1. `0001_initial_schema.sql`: ایجاد جداول `users`، `teams`، `team_members`، `telemetry_pings`، `incidents`، `tactical_messages`، `audit_logs` و تمام ایندکس‌های کارایی.
2. `0002_seed_demo_data.sql`: پر کردن اطلاعات نمایشی ساختگی با هش‌های Web Crypto PBKDF2 برای حساب‌های نمایشی.

### اجرای محلی مایگریشن‌ها
```bash
npm run d1:migrate:local
# یا مستقیماً:
npx wrangler d1 migrations apply DB --local
```

### اجرای مایگریشن بر روی سرور واقعی (نیاز به تایید صریح اپراتور)
> [!CAUTION]
> اجرای دستورات روی دیتابیس ابری ریموت نیاز به احراز هویت در Cloudflare و تایید صریح سرپرست دارد:
```bash
npx wrangler d1 migrations apply DB --remote
```

## ۶. مرزهای امنیتی و ویژگی‌های حفاظتی (Security Boundaries)

1. **مدیریت رمزهای عبور:** از الگوریتم استاندارد `PBKDF2-HMAC-SHA256` با ۱۰۰,۰۰۰ دور محاسباتی و نمک منحصربه‌فرد بر بستر `crypto.subtle` وب استفاده شده است.
2. **احراز هویت توکن JWT:** امضا و تایید توکن‌ها به صورت توزیع‌شده با الگوریتم `HS256` و مقایسه زمان‌ثابت (`timingSafeEqual`) انجام می‌شود تا در برابر حملات تحلیل زمانی (Timing Attacks) مقاوم باشد.
3. **کنترل دسترسی نقش‌محور (RBAC):** اندپوینت‌های مدیریتی (مانند فهرست جامع تیم‌ها یا رادار زنده تله‌متری) به نقش‌های `COMMANDER` و `OWNER` محدود هستند و تلاش سرتیم‌های میدانی برای واکشی اطلاعات سایر تیم‌ها با خطای ۴۰۳ مسدود می‌شود.
4. **پالایش امن لاگ‌ها:** میدلور لاگر هیچ‌گونه پسورد، توکن احراز هویت یا اطلاعات محرمانه کاربر را در کنسول و لاگ‌ها ذخیره نمی‌کند.
5. **فرمت پاسخ‌های خطا:** تمامی پاسخ‌های خطا از استاندارد ساختاریافته RFC-7807 تبعیت کرده و از انتشار پشته فراخوانی کد (Stack Trace) یا اطلاعات حساس سرور به کلاینت جلوگیری می‌کند.

## ۷. فرآیند استقرار در محیط ابری (Deployment Policy)

> [!IMPORTANT]
> استقرار در محیط عملیاتی و تغییر دیتابیس ابری به تایید صریح اپراتور و سرپرست پروژه نیاز دارد. در این فاز (Phase 5) هیچ کدی در محیط پروداکشن دیپلوی نشده است.

در صورت تایید صریح در آینده، مراحل استقرار به صورت زیر خواهد بود:
1. ایجاد پایگاه داده D1 در داشبورد کلودفلر: `npx wrangler d1 create waymate-d1`
2. به‌روزرسانی `database_id` در `wrangler.jsonc`
3. تنظیم کلید رمز در متغیرهای ابری: `npx wrangler secret put JWT_SECRET`
4. اعمال مایگریشن‌ها در دیتابیس ابری: `npx wrangler d1 migrations apply DB --remote`
5. استقرار سرویس Workers: `npx wrangler deploy`
